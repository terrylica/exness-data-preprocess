## 2.1.1 (2026-10-19)

This release changes no query results; it makes the project trustworthy to maintain from Linux. Releases cut on Linux could not bump the version, because the release config used macOS-only `sed -i ''`. Both shipped examples crashed against the v2 API. The ClickHouse tests went red on any host whose `:8123` belonged to a password-protected server. The type-check gate had been failing unnoticed. Each of those is fixed, and there is now a hermetic end-to-end gate, `moon run repo:e2e`: it starts a throwaway ClickHouse, loads real Exness months, runs every test and validation check plus the example, and removes everything it created. Around 11.5k lines of DuckDB-era plans, archives and duplicate tooling are gone, so what remains describes the ClickHouse-only package as it is.

### Fixed

- Releases from Linux: the version bump is now `uv version <next> --frozen`, and `__version__` is read from installed metadata, so `pyproject.toml` is the only place the version lives (#4, #9).
- `examples/basic_usage.py` is rewritten for the v2 API and runs inside the E2E gate; the broken `batch_processing.py` is removed (#5, #9).
- ClickHouse-backed tests use a single authenticated probe that honours `CLICKHOUSE_*`, and skip with the real reason instead of erroring (#6, #9).
- mypy is clean (15 errors to 0). DataFrames are inserted with clickhouse-connect's `insert_df`, its documented DataFrame API (#7, #9).
- Month downloads are atomic (`.part` file renamed on success), so an interrupted download can no longer leave a truncated ZIP that later runs reuse (#9).
- The OHLC table is documented everywhere as 27 columns; some docstrings and the table COMMENT said 26 (#8, #9).

### Added

- `moon run repo:e2e`: hermetic ClickHouse E2E under a `systemd-run` memory cap, with `EXNESS_REQUIRE_CLICKHOUSE=1` so it cannot pass by skipping (#6, #9).
- `EXNESS_DOWNLOAD_DIR` environment variable to choose where month ZIPs are downloaded (default unchanged: `~/eon/exness-data/temp`) (#9).
- A `clickhouse` pytest marker; `-m clickhouse` / `-m "not clickhouse"` select the server-dependent tests (#9).
- Dependabot for pre-commit hooks, GitHub Actions and the semantic-release toolchain (#8, #9).

### Removed

- Duplicate tooling: the commitizen version config, git-cliff configs, the Makefile, the local PyPI publish script (PyPI Trusted Publishing via `publish.yml` is the only publish path), the scheduled pre-commit-autoupdate workflow, and the one-time DuckDB to ClickHouse migration scripts (#8, #9).
- DuckDB-era documentation: completed plans, archives, v1 validation logs, and the obsolete `DATABASE_SCHEMA.md` / `MODULE_ARCHITECTURE.md`. ADRs, design specs and research studies are kept (#8, #9).
