## 3.0.0 (2026-10-19)

This release is about trusting the numbers this package stores and reports. The tick tables silently merged distinct Exness ticks that shared a timestamp: about 0.17% of Raw_Spread ticks on recent EURUSD months, gone without a trace. Date filters were shifted by the server's UTC offset whenever ClickHouse ran outside UTC. Storage size, the up-to-date bar count and `force_redownload` were placeholders that returned 0, ticks ÷ 1000 and nothing at all. Each is now measured and gated by `repo:e2e`, which loads real Exness months on a deliberately non-UTC server and checks that every inserted tick survives a merge, that re-loading changes nothing, and that pagination returns every tick sharing a timestamp. It is a major version for three reasons: the tick tables gain a `seq` column and a new sort key (existing tables are migrated in place automatically), the pagination cursor format changed, and the unused `config` parameter and PyYAML dependency are gone.

### Upgrading

- Nothing to do for the schema: the first `ExnessDataProcessor()` against a pre-3.0 database migrates both tick tables in place (`ADD COLUMN seq`, `MODIFY ORDER BY (instrument, timestamp, seq)`) and logs a warning.
- To recover ticks the old key already merged away, re-load the affected months: `update_data(pair, start_date=..., force_redownload=True)`.
- Remove any `ExnessDataProcessor(config=...)` argument; configure with `CLICKHOUSE_*` and `EXNESS_DOWNLOAD_DIR` environment variables.
- Treat `CursorResult.next_cursor` as opaque (`"<timestamp>#<seq>"`); pass it back unchanged.
- `clickhouse-connect` 1.11.0 or newer is now required.

### Fixed

- Distinct ticks that share a timestamp are kept: tick tables deduplicate on `(instrument, timestamp, seq)`, with `seq` numbering same-timestamp ticks in source order, so re-loading a month stays idempotent (#23).
- Date filters are no longer shifted on non-UTC ClickHouse servers; every datetime parameter is bound as `DateTime64(6, 'UTC')` (#24).
- A date-only `end_date` now includes that whole day, as documented; it used to stop at 00:00:00 of that day (#24).
- Counts, tick and OHLC queries, and the OHLC build read with `FINAL`, so results are correct before ClickHouse's background merges; a re-load had reported 157,316 bars for 78,658 (#23).
- `update_data(force_redownload=True)` now re-processes every month from `start_date`; it was previously accepted and ignored (#23).
- Cursor pagination no longer skips ticks that share the last timestamp of a page (#23).
- `storage_bytes` reports the real on-disk size of the package tables, and the up-to-date path of `update_data` reports the real OHLC bar count instead of ticks ÷ 1000 (#19, #20).

### Removed

- `exness_data_preprocess.config` (`ConfigModel`, `load_config`, `get_default_config_path`), the `ExnessDataProcessor(config=...)` parameter, and the PyYAML runtime dependency, none of which had any effect (#21, #22).

### Known issues

- `ohlc_1m.tick_count_standard` equals the Raw_Spread tick count of each minute rather than counting Standard ticks; this predates 3.0.0 and is tracked in #25.
